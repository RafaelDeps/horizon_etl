# Implementation Plan: Weekly CI Workflow Validation and Export Compression

**Branch**: `feat/003-workflow-ci-zip-exports` | **Date**: 2026-05-16 | **Spec**: [spec.md](spec.md)

## Summary

Fix the `weekly-etl.yml` GitHub Actions workflow to resolve three issues: missing `actions: write` permission (blocks artifact upload), absent Chrome/chromedriver for the Lattes Selenium flow, and uncompressed exports exceeding the 10 MB threshold. All changes are confined to a single YAML file.

**Amendment (2026-10-14)** — publish the curated archive through git:

Instead of leaving `exports_canonical.zip` to be downloaded from the 30-day
artifact list and committed by hand, the workflow now commits the archive it
just generated back to the repository. Four changes to `.github/workflows/weekly-etl.yml`:

1. `permissions.contents` `read` → `write` (required to push the commit).
2. The pre-upload compression step skips every `*.zip`, so `exports_canonical.zip`
   is delivered byte-for-byte as `zip_exports_task` wrote it (today it is
   re-wrapped into a nested `exports_canonical.zip.zip`).
3. A new "Commit exports_canonical.zip if changed" step runs only on success;
   it stages `data/exports/exports_canonical.zip`, and commits + pushes it only
   when the staged content differs.
4. The artifact upload excludes `!data/exports/exports_canonical.zip`, so the
   archive is no longer a manually downloadable artifact — git is its channel.

## Changes in Detail

### 1. Permissions: `actions: write` + `contents: write`

```yaml
permissions:
  contents: write       # required to push the archive commit
  actions: write        # required by upload-artifact@v4
```

### 2. Install Chromium apt pair for Lattes (after Playwright install step)

```yaml
- name: Install Chromium for Lattes (Selenium)
  run: |
    sudo apt-get update -qq
    sudo apt-get install -y chromium-browser chromium-driver
```

Add env vars at job level:

```yaml
env:
  CHROME_BINARY: /usr/bin/chromium-browser
  CHROMEDRIVER_PATH: /usr/bin/chromedriver
```

### 3. Compress exports >10 MB before upload (never `.zip`)

```yaml
- name: Compress large export files
  if: always()
  run: |
    # Never touch archives: exports_canonical.zip is the flow's own deliverable.
    find data/ -type f -size +10M ! -name '*.zip' \
      -exec sh -c 'for f; do zip -m -j "$f.zip" "$f"; done' sh {} +
```

The `! -name '*.zip'` guard is what makes the committed archive identical to the
one `make weekly-flows` wrote; without it the archive is re-wrapped as
`exports_canonical.zip.zip`.

### 4. Commit the archive when it changed

```yaml
- name: Commit exports_canonical.zip if changed
  if: success()
  run: |
    set -euo pipefail
    ZIP="data/exports/exports_canonical.zip"
    if [ ! -f "$ZIP" ]; then
      echo "::warning::$ZIP was not generated; nothing to commit."
      exit 0
    fi
    git add -- "$ZIP"
    if git diff --cached --quiet; then
      echo "No changes to $ZIP; nothing to commit."
      exit 0
    fi
    git config user.name "github-actions[bot]"
    git config user.email "41898282+github-actions[bot]@users.noreply.github.com"
    git commit -m "chore(exports_canonical.zip): update from weekly run $(date -u +%Y-%m-%d)"
    git push origin "HEAD:${{ github.ref_name }}"
```

`if: success()` ensures a partial archive from a failed run is never committed.

### 5. Exclude the archive from the artifact (retention 30 days)

```yaml
- name: Upload ETL artifacts
  if: always()
  uses: actions/upload-artifact@v4
  with:
    name: weekly-etl-artifacts
    retention-days: 30
    if-no-files-found: ignore
    path: |
      data
      db/horizon.db
      !data/exports/exports_canonical.zip
      !.venv
      !.venv/**
      !.env
      !.env.*
```

## Out of Scope

- Caching Docker images between runs
- External artifact storage (S3, GCS)
- Committing any `data/` output other than `exports_canonical.zip`
- Making the archive byte-reproducible across runs
- Multi-campus parallel execution in CI
- Changing pipeline schedule or timeout
